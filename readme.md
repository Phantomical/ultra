# Ultra [![ci](https://github.com/xoofx/ultra/actions/workflows/ci.yml/badge.svg)](https://github.com/xoofx/ultra/actions/workflows/ci.yml) [![NuGet](https://img.shields.io/nuget/v/Ultra.svg)](https://www.nuget.org/packages/Ultra/)

<img align="right" width="160px" height="160px" src="https://raw.githubusercontent.com/xoofx/ultra/main/img/ultra.png">

Ultra is an advanced profiler for .NET Applications available on Windows and macOS (Apple Silicon).

> 📽️ Check this [video](https://vimeo.com/1030852299) for a quick tour of ultra! 📽️

## ✨ Features

- **Sampling profiler** - ETW based on Windows (up to 8190 samples/second), in-process sampler over EventPipe on macOS ARM64 (up to 1000 samples/second)
- UI based on https://profiler.firefox.com/
  - Traces shareable online: Check this example: ✨ https://share.firefox.dev/3Cya7YW ✨
  - **Timeline** visualization
  - **Flamegraph / Stack Chart** visualization
  - **Call Tree** visualization
  - **Marker Chart** and **Marker Table** visualization  
- Precise **kernel**, **native** and **managed** **function call stacks**
- Categorization of functions: 
  - `.NET`, `.NET JIT`, `.NET GC`, `.NET CLR`, `Native`, `Kernel`
  - `.NET GC` covers CoreCLR's collector, Mono's SGen collector (everything called while collecting) and Unity's unused-asset collection
- .NET GC Memory track
- JIT Compile Time Event Markers
  - See which function is getting compiled, its assembly, its IL size and the optimization tier it was compiled at
- Functions attributed to their assembly or native library
- GC Events Markers
  - `GC Allocation Ticks`: Details about allocations. 
  - `GCHeapStats`: Statistics about the GC
  - `GCSuspendEE`, `GCRestartEE`, `GC Start`, `GC Stop` events, paired across threads
  - `GC Concurrent`: the phase of a background collection during which the collector runs alongside your code
- Lightweight trace files - e.g. Generates only a few MB for 10s
- Requires `net8.0+` via dotnet global tool

## 🧑‍💻 Usage

You need to have installed a [.NET 10.0+ SDK](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)

```console
$ dotnet tool install -g Ultra # The command ultra.exe will be available from your PATH
```

### Windows

> ____
> 🚨 The profiler **requires to run from an elevated prompt with administrative rights** 🚨 
>
> _This is required to allow to collect full stack traces, including kernel and native functions. Without it, ultra falls back to a user-mode sampler (`--user-mode-sampling`), without kernel stacks._
> ____

Example: open a **terminal with administrative rights**, to profile an executable called `my_commands.exe`:

```console
$ ultra.exe profile -- my_command.exe arg0 arg1 arg2...
```

> ⚠️ Notice the `--` separator to separate the arguments to `ultra.exe` from the arguments to the profiled application.

Profiling a running application just requires the PID of the process to profile:

```console
$ ultra.exe profile 15243 # PID of the process to profile
# Wait for a bit and press only one CTRL+C to stop the profiling
```

#### Without administrative rights (user-mode sampling)

When ultra is not elevated, or with `--user-mode-sampling`, ultra samples the profiled process from its own process instead of the kernel ETW session: at each tick (1ms by default) it suspends each thread that used CPU since the last sample, copies its registers and stack, resumes it, and walks the stack with the x64 unwind data of the loaded images and of the JIT code registered with the OS (dynamic function tables). The .NET runtime events (JIT method names, GC) are still recorded with a user ETW session, which only requires to be a member of the `Performance Log Users` group.

This mode is Windows x64 only. It has no kernel stacks and no context switches, a thread is sampled in proportion to its CPU time but may be caught in a wait it just entered, and its samples cost the profiled threads a short suspension (tens of microseconds).

### Desktop UI (Windows)

`ultra-ui` is a desktop UI for the same profiler. It is installed separately:

```console
$ dotnet tool install -g Ultra.UI # The command ultra-ui.exe will be available from your PATH
```

- Pick the program to launch (with its arguments, working directory and environment variables) or a process to attach to, then **Start session**. The UI itself runs without administrative rights: with **Run as administrator** checked, it asks Windows for consent and runs the profiler (and the program it launches) elevated, otherwise it uses user-mode sampling.
- Like `--paused`, a session takes as many captures as you want (**Start capture** / **Stop capture**, or F5/F6) until the program exits or you end the session; captures save in the background while the next one profiles.
- Each saved capture has an **Open in Firefox Profiler** button: the UI serves the profile from `127.0.0.1` and opens `profiler.firefox.com/from-url/...`, so there is no file to drag and drop (the link works while the UI is running). You can still drag a capture by its `⠿` handle onto a Firefox Profiler tab.
- **Settings** keeps custom symbol paths (searched before the default symbol servers) and the output folder (`Documents\ultra` by default) in `%APPDATA%\ultra\ui-settings.json`, together with the last launch settings.

### macOS (Apple Silicon)

On macOS, **no elevated privileges are required**. The profiler injects a small sampler library into the launched process to collect native and managed call stacks.

```console
$ ultra profile -- my_command arg0 arg1 arg2...
```

Current limitations on macOS:

- Only **ARM64** (Apple Silicon) is supported.
- Only **launching a program** is supported - attaching to a running process with a PID is not (the sampler library can only be injected at process startup).
- The maximum sampling frequency is 1000 samples/second (`--sampling-interval` minimum is 1ms).
- Kernel call stacks are not collected (user-space native and managed call stacks are).
- Symbols of system libraries living in the dyld shared cache (e.g. `libsystem_pthread.dylib`) are not resolved.
